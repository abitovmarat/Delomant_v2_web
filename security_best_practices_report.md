# Аудит демонстрационной сборки для экспертизы реестра ПО

Дата проверки: 19.08.2026  
Область проверки: исходный проект и каталог сборки `dist/`; экспертная роль; признаки поддержки детализированных/контрагентских таможенных выгрузок; связанные меры безопасности.

## Резюме

**Итог: требование «эксперт не должен видеть, что программа умеет работать с закрытыми детализированными таможенными выгрузками» сейчас не выполнено.**

Экспертная роль не получает российские декларации и не может загрузить файл штатной кнопкой, однако получает тот же HTML и тот же JavaScript, что и полная роль. Стенд прямо сообщает о закрытой функции загрузки таможенной выгрузки, а исходный код содержит подробный маппинг полей декларации: номер декларации, ИНН отправителя/получателя, контрактодержатель, таможенный орган и таможенная стоимость. Те же возможности прямо описаны в материалах для экспертизы.

Положительные результаты:

- российских деклараций и реальных клиентских выгрузок в `dist/` не обнаружено;
- PHP endpoint для приёма CSV/XLS/XLSX отсутствует;
- пользовательский файл читается локально через `FileReader`, сервер его не получает;
- приложение и ассеты закрыты PHP-сессией;
- административная страница отдельно проверяет роль `full`.

Рекомендуемое решение — не маскировать одну полную сборку, а сформировать отдельную реально ограниченную редакцию для экспертизы: отдельные HTML/JS/данные, в которых физически отсутствуют загрузчик деклараций, маппинг полей ФТС/ГТД и контрагентские анализы. Документы должны точно описывать именно передаваемую редакцию. Если объект регистрации — полная программа с локальной обработкой пользовательских файлов, скрывать эту функцию в документах нельзя; вместо этого следует честно отделить программу от прав на загружаемые пользователем данные.

## Высокий приоритет

### RR-001 — Эксперт получает исходники полной версии

- **Серьёзность:** High
- **Расположение:** `server/index.php:121-135`, `server/asset.php:22`, `server/asset.php:44`, `index.html:318-405`, `scripts/main.js:3-75`
- **Доказательство:** `index.php` для обеих ролей читает один `app/index.html` и меняет только значение `<meta name="app-role">`. `asset.php` проверяет только наличие `$_SESSION['auth']` и для обеих ролей отдаёт один `main.js.dat`. Полный HTML содержит элементы загрузки и обработки, а JavaScript удаляет/заменяет их уже в браузере.
- **Воздействие:** проверяющий может увидеть полную функциональность через View Source, DevTools или скачанный `main.js`. Полученные HTML/JS можно сохранить локально и запустить с изменённой ролью, поскольку обработка файлов целиком клиентская.
- **Исправление:** собирать отдельные `expert/index.html` и `expert/main.js`, в которых запрещённые модули отсутствуют на уровне исходного артефакта. `index.php` и `asset.php` должны выбирать артефакт по серверной роли.
- **Временное снижение риска:** не рекламировать закрытые функции в экспертном UI и не отдавать экспертной роли общие исходники; это временная мера, а не замена отдельной сборки.
- **Примечание о ложном срабатывании:** штатный обработчик `handleFile()` действительно прекращает работу при `isExpert`, но это не устраняет раскрытие исходного кода и возможности локального запуска полученного клиентского кода.

### RR-002 — Стенд явно рекламирует закрытую функцию

- **Серьёзность:** High
- **Расположение:** `scripts/main.js:26-28`, `scripts/main.js:39-44`, `scripts/main.js:59-73`
- **Доказательство:** комментарий говорит «Закрытые возможности не прячем, а помечаем замком»; пользователю выводятся «другой тариф», «Раздел принимает вашу таможенную выгрузку» и «Загрузка своей выгрузки (CSV, XLS, XLSX)».
- **Воздействие:** наличие функции видно без технического анализа прямо в интерфейсе экспертной роли.
- **Исправление:** в отдельной экспертной редакции полностью исключить этот промоблок и сам модуль, если функция не входит в объект, предъявляемый на экспертизу.
- **Временное снижение риска:** заменить раздел нейтральным описанием только тех открытых источников и операций, которые реально входят в экспертную редакцию.
- **Примечание о ложном срабатывании:** отсутствует — текст показывается именно роли `expert`.

### RR-003 — Код однозначно распознаёт структуру детализированной декларации

- **Серьёзность:** High
- **Расположение:** `scripts/main.js:3244-3460`, `scripts/main.js:3504-3626`, `scripts/main.js:9970`, `scripts/main.js:10372`
- **Доказательство:** в общем клиентском файле присутствуют соответствия для `ND (Номер декларации)`, `G021 (ИНН отправителя)`, `G081 (ИНН получателя)`, `G092 (Наименование контрактодержателя)`, `G3012 (Код таможенного органа)` и `G12 (Общая таможенная стоимость по ГТД)`.
- **Воздействие:** даже без демонстрационных российских строк исходный код доказывает техническую готовность программы работать с детализированными декларационными выгрузками.
- **Исправление:** вынести этот маппинг и зависящие от него анализы в отдельный модуль полной редакции; не включать модуль в исходники и бинарные/веб-артефакты экспертной редакции.
- **Временное снижение риска:** минификация или обфускация не считаются исправлением: строки полей всё равно извлекаются, а функциональность остаётся в поставке.
- **Примечание о ложном срабатывании:** названия полей сами по себе не доказывают наличие незаконно полученных данных, но однозначно раскрывают поддерживаемый формат и назначение функции.

### RR-004 — Материалы экспертизы сами раскрывают полную функцию

- **Серьёзность:** High
- **Расположение:** `docs/reestr/01_Описание_ПО.md:7-10`, `docs/reestr/01_Описание_ПО.md:27-40`, `docs/reestr/01_Описание_ПО.md:67-70`, `docs/reestr/expertiza/2_Функциональные_характеристики.md:9-12`, `docs/reestr/expertiza/2_Функциональные_характеристики.md:27-40`, `docs/reestr/10_Правовой_контур_данных_и_план_подачи.md:42`
- **Доказательство:** документы заявляют загрузку таможенных выгрузок, контрагентскую аналитику и алгоритмы локального разбора CSV/XLSX/XLS.
- **Воздействие:** даже идеально ограниченный стенд не решит задачу, если передаваемый комплект документов описывает полную редакцию.
- **Исправление:** сначала формально определить объект регистрации. Для отдельной open-data редакции подготовить согласованный комплект описания, архитектуры, руководств и функциональных характеристик именно этой редакции. Для полной редакции сохранить правдивое описание и документально отделить права на программу от прав на пользовательские данные.
- **Временное снижение риска:** составить матрицу «заявленная функция → файл поставки → экран стенда → раздел документа» и устранить расхождения до подачи.
- **Примечание о ложном срабатывании:** это не уязвимость авторизации; это критичное несоответствие поставленной цели подготовки к экспертизе.

## Средний приоритет

### RR-007 — В поставку входит словарь с реальными российскими наименованиями

- **Серьёзность:** Medium
- **Расположение:** `data/company_dictionary.json:1-18`, `build.mjs:48`, `server/asset.php:48`
- **Доказательство:** словарь содержит, в частности, наименования российских организаций (`ООО`, рыболовецкая артель) и включается в `dist/assets/company_dictionary.dat`.
- **Воздействие:** это не декларации и не ИНН, но наличие реальных российских наименований в демонстрационной поставке создаёт лишний вопрос об источнике словаря и связи с клиентскими выгрузками.
- **Исправление:** заменить словарь экспертной редакции синтетическими примерами или пустым документированным шаблоном.
- **Временное снижение риска:** исключить ключ `dict` из карты ассетов экспертной роли.
- **Примечание о ложном срабатывании:** по найденному содержимому нельзя утверждать, что словарь получен из закрытой статистики; риск относится к происхождению и восприятию поставки.

### SEC-001 — Нет видимой CSP и контроля целостности сторонних скриптов

- **Серьёзность:** Medium
- **Расположение:** `index.html:55`, `index.html:978-982`, `server/htaccess:1-47`
- **Доказательство:** CSP в репозитории не найдена; пять библиотек загружаются с CDN без атрибута `integrity`. В клиентском коде используется большое количество `innerHTML`.
- **Воздействие:** компрометация CDN или DOM-XSS может дать выполнение кода в авторизованном приложении и доступ к данным, обрабатываемым в браузере.
- **Исправление:** по возможности самостоятельно размещать зафиксированные версии библиотек; иначе добавить SRI; ввести CSP через HTTP-заголовок и постепенно устранить небезопасные HTML-вставки.
- **Временное снижение риска:** ограничить `script-src` точным списком источников и зафиксированными версиями; проверить фактические заголовки на production/edge, поскольку они могут задаваться вне репозитория.
- **Примечание о ложном срабатывании:** заголовки могут устанавливаться nginx/CDN вне проекта; это необходимо проверить на развёрнутом стенде.

## Проверки и ограничения

- Выполнен поиск по исходникам, документам, данным и готовому `dist/` по признакам российских деклараций, контрагентских полей, загрузки файлов, авторизации и источников данных.
- Проверено, что серверные PHP-файлы не используют `$_FILES`, `move_uploaded_file` или чтение `php://input` для пользовательских таблиц.
- Синтаксис `scripts/main.js` и `build.mjs` проверен командой `node --check` — ошибок не обнаружено.
- PHP CLI в среде отсутствует, поэтому `php -l` выполнить не удалось.
- Специализированного профиля PHP в применённом security-навыке нет; PHP проверялся по общим правилам контроля доступа, сессий, выдачи ассетов и минимизации данных.
- Юридическая допустимость пользовательских данных в рамках этого технического аудита не устанавливалась.

## Критерий готовности перед передачей эксперту

Сборку можно считать соответствующей поставленной цели только если одновременно выполнено следующее:

1. Эксперт получает отдельные HTML и JS без загрузчика деклараций и без маппинга полей ГТД/ФТС.
2. Серверная роль `expert` не может получить ассеты полной редакции прямым URL.
3. В экспертной поставке нет российских компаний, ИНН и деклараций.
4. UI не показывает замки, «другой тариф» и описания скрытых таможенных выгрузок.
5. Все документы описывают именно переданную редакцию и не противоречат её фактической функциональности.
6. Все демонстрационные данные синтетические либо имеют проверяемый источник и основание повторного использования.
