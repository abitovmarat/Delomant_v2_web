# Инструкция по установке и развёртыванию

Инструкция относится к **Delomant — Аналитика ВЭД**, версия 0.9. Приложение
разворачивается на веб-сервере; установка на рабочие места пользователей не
требуется.

## 1. Фактическая площадка

- Провайдер/площадка: Cloud4box.
- Серверный узел: `web-3.cloud4box.com`.
- IPv4: `185.154.20.52` (DNS проверен 10.08.2026).
- Публичный адрес: `https://delomant-analytics-system.ru/`.
- Публикация: GitHub Actions → FTPS.
- Юридическое лицо провайдера и расположение ЦОД: ⚠️ подтвердить договором или
  документами из панели хостинга.

## 2. Требования

### 2.1. Среда сборки

- Node.js 22 — версия, закреплённая в `.github/workflows/deploy.yml`;
- доступ на чтение исходников и право пересоздать каталог `dist/`;
- переменная `SETUP_TOKEN` для контролируемого токена первичной установки;
- необязательная переменная `COMTRADE_KEY` для Comtrade Plus.

Установка npm-пакетов для выполнения `node build.mjs` не требуется: сборщик
использует только стандартные модули Node.js.

### 2.2. Веб-сервер

- nginx перед Apache либо Apache напрямую;
- Apache с `mod_rewrite` и разрешёнными правилами `.htaccess`;
- PHP 8+;
- расширения PHP cURL, SimpleXML и JSON;
- стандартные PHP-сессии и функции `password_hash`, `random_bytes`;
- HTTPS — обязательно, поскольку cookie сессии имеет атрибут `Secure`;
- возможность PHP создавать файлы в корне сайта и каталог `/cache/`;
- исходящие HTTPS-соединения сервера к `comtradeapi.un.org` и
  `wits.worldbank.org`.

### 2.3. Рабочее место пользователя

- современный браузер с JavaScript, File API, SVG и Canvas;
- доступ по HTTPS к приложению;
- в текущей реализации — доступ браузера к `cdn.sheetjs.com`,
  `cdnjs.cloudflare.com` и `cdn.jsdelivr.net`.

Если браузерные библиотеки будут перенесены в дистрибутив, последнее требование
следует удалить из инструкции.

## 3. Сборка дистрибутива

В корне репозитория выполнить:

```bash
node build.mjs
```

Для воспроизводимой первичной установки рекомендуется явно задать токен:

```bash
SETUP_TOKEN=<секретный-токен> COMTRADE_KEY=<необязательный-ключ> node build.mjs
```

Конкретный синтаксис задания переменных зависит от оболочки и системы CI.
Значения токенов, паролей и ключей API в документацию и репозиторий не
включаются.

Сборка полностью пересоздаёт `dist/` и формирует следующую структуру:

```text
dist/
├── .htaccess
├── index.php
├── asset.php
├── admin.php
├── setup.php
├── comtrade.php
├── wits.php
├── comtrade_key.php       # только если задан COMTRADE_KEY
├── app/index.html
└── assets/
    ├── main.js.dat
    ├── main.css.dat
    ├── *.json → *.dat
    └── *.dat.gz           # для крупных файлов
```

Если `SETUP_TOKEN` не задан, сборщик создаёт случайный токен и печатает его в
консоль. Для автоматизированной первичной установки значение необходимо
сохранить из защищённого журнала сборки.

## 4. Ручная выкладка

1. Загрузить **содержимое** `dist/` в корневой каталог сайта.
2. Убедиться, что `.htaccess` загружен и применяется Apache.
3. Проверить права PHP на создание `/config.php`, `/users.php` и `/cache/`.
4. Открыть `https://<домен>/setup.php?token=<SETUP_TOKEN>`.
5. Задать пароль владельца и, при необходимости, общий экспертный пароль.
6. После успешной настройки убедиться, что повторный запуск `setup.php`
   заблокирован наличием `config.php`.
7. Открыть корень сайта и выполнить вход.

`setup.php` сохраняет только bcrypt-хеши паролей в `/config.php` и назначает
файлу права `0600`, если это поддерживается хостингом. Пароли в открытом виде
не сохраняются.

## 5. Создание экспертной учётной записи

1. Войти по общему паролю владельца, оставив поле логина пустым.
2. Открыть `/admin.php`.
3. Указать логин, ФИО и пароль проверяющего.
4. Проверить вход созданной учётной записью.

Персональная учётная запись получает роль `expert`. Аккаунты хранятся в
`/users.php` в виде PHP-массива с bcrypt-хешами паролей.

## 6. Проверка развёртывания

После установки проверить:

1. без авторизации корень сайта показывает форму входа;
2. прямой запрос к `/assets/main.js.dat` возвращает запрет доступа;
3. после входа загружаются интерфейс, стили, логотип и JSON-справочники;
4. роль `full` видит загрузку пользовательских файлов и ссылку на
   `/admin.php`;
5. роль `expert` сначала видит личный кабинет, а на стенде — ограниченный
   интерфейс без пользовательской контрагентской выгрузки;
6. запросы UN Comtrade и WITS возвращают данные либо понятное сообщение об
   ошибке внешнего источника;
7. в каталоге `/cache/` создаются файлы кеша;
8. работают загрузка синтетического файла и экспорт XLSX/PDF/PPTX/HTML;
9. выход завершает сессию и возвращает форму входа.

## 7. Автоматическая публикация

Workflow `.github/workflows/deploy.yml` запускается при отправке изменений в
ветку `master`.

Необходимые GitHub Secrets:

| Секрет | Назначение |
|---|---|
| `FTP_SERVER` | Адрес FTPS-сервера |
| `FTP_USERNAME` | Имя пользователя |
| `FTP_PASSWORD` | Пароль |
| `FTP_SERVER_DIR` | Корневой каталог сайта на сервере |
| `COMTRADE_KEY` | Необязательный ключ Comtrade Plus |

Workflow собирает `dist/` в Node.js 22 и передаёт его одной FTPS-сессией через
`lftp mirror -R` без общего `--delete`. Благодаря этому `/config.php`,
`/users.php` и `/cache/`, отсутствующие в `dist/`, сохраняются на сервере.

> ⚠️ ЗАПОЛНИТЬ: фактическое значение каталога размещения описать без раскрытия
> учётных данных; подтвердить юридическое лицо провайдера, расположение ЦОД и
> реквизиты договора.

## 8. Обновление справочников

Отслеживаемые репозиторием служебные команды:

```bash
node scripts/fetch_comtrade_countries.js
node scripts/sync_wits_country_names.js
```

Первая команда обновляет справочник стран UN Comtrade. Вторая переносит
проверенные русские наименования в уже существующий справочник WITS.

`data/cbr_rates.json` входит в дистрибутив как статический файл. Скрипт его
обновления в текущей версии не отслеживается Git, поэтому перед фиксацией
релиза необходимо либо включить воспроизводимый генератор в репозиторий, либо
утвердить отдельный регламент обновления с указанием источника, периода и
ответственного.

После изменения любого файла из `data/` нужно повторно собрать и опубликовать
`dist/`.

## 9. Обновление и откат

Перед публикацией новой версии сохранить резервные копии `/config.php`,
`/users.php` и, если используется, `/comtrade_key.php`. Каталог `/cache/`
содержит воспроизводимые данные и может быть очищен отдельно при изменении
формата ответов.

Для отката повторно собрать и опубликовать зафиксированный предыдущий коммит.
Эксплуатационные файлы с паролями и аккаунтами не должны заменяться файлами из
репозитория.
