# Описание технической архитектуры программного обеспечения

**Программа для ЭВМ:** Delomant Analytics System

**Версия заявляемого экземпляра:** 0.9

**Правообладатель:** ООО «ДЕЛОМАНТ ГРУПП»

---

## 1. Общая схема построения

Delomant Analytics System построена по клиент-серверной схеме с тонким
серверным слоем. Основная прикладная логика выполняется в браузере
пользователя, серверная часть отвечает за вход и разграничение доступа,
защищённую выдачу файлов приложения и обращение к внешним открытым
источникам данных.

Пользователь работает с программой через браузер по протоколу HTTPS.
Установка программы или расширений браузера на рабочее место не требуется.

Отдельная система управления базами данных не применяется. Данные,
обрабатываемые пользователем, находятся в оперативной памяти браузера и на
сервер не передаются.

## 2. Клиентская часть

Клиентская часть написана на HTML5, CSS3 и JavaScript без прикладного
фреймворка.

| Компонент | Назначение |
|---|---|
| `index.html` | Разметка одностраничного приложения |
| `scripts/main.js` | Прикладная логика: получение данных, расчёты, построение графиков, экспорт |
| `styles/main.css` | Оформление интерфейса и экспортируемых материалов |
| `data/*.json` | Справочники стран, регионов, товарных кодов и курсов валют |

В браузере выполняются:

- запрос данных открытых источников через серверные посредники;
- расчёт аналитических показателей;
- построение графиков средствами SVG и Canvas;
- формирование и сохранение материалов в форматах PPTX, PDF, HTML, XLSX,
  CSV и PNG.

Роль пользователя передаётся приложению служебным полем разметки, которое
серверная часть подставляет при выдаче страницы. Для роли эксперта интерфейс
скрывает разделы, не входящие в заявляемую версию.

### 2.1. Сторонние библиотеки

Клиентские библиотеки поставляются вместе с программой и выдаются с домена
приложения. Обращений к сторонним сетям доставки содержимого во время работы
программа не выполняет: работа не должна зависеть от доступности внешних
сетевых узлов.

| Библиотека | Версия | Назначение | Лицензия |
|---|---|---|---|
| SheetJS Community Edition | 0.20.3 | Чтение и запись XLSX | Apache-2.0 |
| JSZip | 3.10.1 | Упаковка файлов экспорта | MIT либо GPL-3.0 |
| jsPDF | 2.5.1 | Формирование PDF | MIT |
| html2canvas | 1.4.1 | Преобразование разметки в изображение | MIT |
| PptxGenJS | 3.12.0 | Формирование презентаций PPTX | MIT |

Для каждой библиотеки хранятся текст лицензии, исходный адрес загрузки и
контрольная сумма SHA-256 распространяемого файла.

## 3. Серверная часть

Серверная часть выполнена на PHP 8 и состоит из независимых точек входа.

| Компонент | Назначение |
|---|---|
| `index.php` | Форма входа, сессия, разграничение ролей, выдача приложения либо личного кабинета |
| `asset.php` | Выдача файлов приложения после проверки сессии |
| `admin.php` | Управление персональными учётными записями, доступ только роли полного доступа |
| `setup.php` | Первичное создание конфигурации с хешами паролей |
| `comtrade.php` | Проверка параметров, ограничение частоты, кеширование и обращение к UN Comtrade |
| `wits.php` | Проверка параметров, кеширование, запрос и разбор ответа World Bank WITS |
| `docs.php` | Публичная страница документации, доступная без авторизации |
| `.htaccess` | Правила маршрутизации и запрет прямого доступа к внутренним файлам |

Файлы приложения размещаются на сервере под изменёнными именами и закрыты
правилами веб-сервера. Обычные пути, к которым обращается клиентская часть,
перенаправляются на компонент выдачи, который проверяет сессию.

Крупные файлы дополнительно хранятся в сжатом виде. Компонент выдачи
выбирает сжатую копию, если браузер сообщил о поддержке сжатия, и использует
заголовки ETag и Last-Modified для повторного использования уже загруженных
файлов.

## 4. Программное окружение

| Уровень | Средство |
|---|---|
| Веб-сервер | nginx, за ним Apache с модулем `mod_rewrite` |
| Среда выполнения серверной части | PHP 8 |
| Расширения PHP | cURL, SimpleXML, JSON |
| Протокол доступа пользователей | HTTPS |
| Система управления базами данных | не применяется |
| Средства виртуализации и контейнеризации | не применяются |

## 5. Данные на сервере

На развёрнутом экземпляре создаются и хранятся:

| Объект | Содержание | Порядок создания |
|---|---|---|
| Файл конфигурации | Хеши общих паролей | Компонент первичной настройки |
| Файл учётных записей | Персональные учётные записи и хеши паролей | Компонент управления учётными записями |
| Файл ключа доступа | Необязательный ключ внешнего источника | Сборочный сценарий из защищённого хранилища секретов |
| Каталог кеша | Ответы открытых источников со сроком хранения 24 часа | Серверные посредники |

Пользовательские данные на сервере не сохраняются.

## 6. Потоки данных

**Открытая статистика UN Comtrade.** Браузер обращается к серверному
посреднику, тот проверяет сессию и параметры запроса, возвращает ответ из
кеша либо запрашивает его у источника. Полученные сведения передаются в
браузер, где выполняются расчёты и формирование материалов.

**Открытая статистика World Bank WITS.** Порядок тот же; ответ источника
разбирается на сервере и передаётся в браузер в нормализованном виде.

**Справочники.** Справочники стран, регионов, товарных кодов и курсов валют
выдаются компонентом выдачи файлов после проверки сессии.

**Материалы пользователя.** Расчёты и формирование отчётов выполняются в
браузере, готовый файл сохраняется на компьютер пользователя. На сервер
приложения эти данные не передаются.

## 7. Модель безопасности

- доступ к приложению, его файлам и серверным посредникам защищён единой
  сессией;
- файл сессии передаётся с атрибутами `Secure`, `HttpOnly` и `SameSite=Lax`;
- после успешного входа идентификатор сессии создаётся заново;
- пароли хранятся только в виде хешей, полученных по алгоритму bcrypt;
- управление учётными записями доступно только роли полного доступа и
  защищено проверочным токеном;
- параметры запросов к внешним источникам проверяются по спискам
  допустимых значений;
- частота обращений к внешним источникам ограничена;
- прямой доступ к файлам конфигурации, учётных записей, ключей и кеша
  запрещён правилами веб-сервера;
- пользовательские данные на сервере не сохраняются.

Публичная страница документации открыта без авторизации намеренно и отдаёт
только заранее определённый перечень файлов; на доступ к приложению это не
влияет.

## 8. Подготовка к выпуску и размещение

Исходный текст хранится в репозитории Git на российской платформе GitVerse.

Сборочный сценарий на Node.js 22 формирует комплект файлов для размещения:
копирует серверные компоненты и правила веб-сервера, размещает файлы
приложения под защищёнными именами, добавляет справочники и библиотеки,
создаёт сжатые копии крупных файлов и подставляет метку версии сборки.

Размещение выполняется конвейером платформы по защищённому протоколу FTPS
одним сеансом связи. Выкладка не удаляет файлы конфигурации, учётных записей
и кеша, поэтому доступ пользователей и накопленный кеш сохраняются между
обновлениями.

Компиляция исходного текста в объектный код не выполняется: используемые
языки интерпретируемые.
