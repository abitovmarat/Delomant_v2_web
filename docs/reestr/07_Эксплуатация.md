# Документы по эксплуатации

<a id="требования"></a>

## Требования к программному и аппаратному обеспечению

### Рабочее место пользователя
- Современный браузер (Chrome, Yandex Browser, Firefox, Edge — актуальные версии).
- Разрешение экрана от 1280×800.
- Доступ по HTTPS к стенду и, пока библиотеки не включены в дистрибутив, к
  `cdn.sheetjs.com`, `cdnjs.cloudflare.com` и `cdn.jsdelivr.net`.
- Установка ПО на рабочее место не требуется.

### Сервер (площадка размещения)
- ОС: Linux (типовой веб-хостинг).
- Веб-сервер: Apache (`.htaccess`) за nginx.
- PHP 8+ с поддержкой сессий и расширениями cURL, SimpleXML, JSON.
- HTTPS-сертификат.
- Исходящий HTTPS-доступ к UN Comtrade и World Bank WITS.
- Права PHP на создание `config.php`, `users.php` и каталога `cache/`.
- Дисковое пространство: приложение, JSON-справочники и файловый кеш внешних
  API; ⚠️ ЗАПОЛНИТЬ фактические значения ОЗУ, CPU и диска тарифа хостинга.

<a id="обновление"></a>

## Порядок обновления ПО

Обновление выполняется правообладателем централизованно на стороне сервера;
действий со стороны пользователей не требуется.

1. Внести изменения в исходный код.
2. Собрать новый дистрибутив: `node build.mjs`.
3. Выложить содержимое `dist/` на хостинг (замена файлов).
4. Файлы `config.php`, `users.php` и каталог `cache/` при штатном обновлении
   **не затрагиваются**.
5. Обновление версии отражается в разделе «О программе».

Обновление справочных данных — перегенерация JSON офлайн-скриптами и
перевыкладка (см. [04_Установка_и_развертывание.md](04_Установка_и_развертывание.md)).

> ⚠️ ЗАПОЛНИТЬ: политика версионирования (semver/дата), периодичность обновлений,
> канал уведомления пользователей об обновлениях.

<a id="устранение-неисправностей"></a>

## Устранение неисправностей

Приложение статично со стороны сервера: сбои носят точечный характер и не
требуют развитой процедуры инцидент-менеджмента.

| Симптом | Причина | Устранение |
|---|---|---|
| Вместо приложения открывается форма установки | Не создан `config.php` (первый запуск или файл утерян) | Открыть `setup.php` с токеном установки, задать пароль заново |
| «Прокси comtrade.php недоступен или вернул не JSON» / аналогично для WITS | Сбой публичного API ООН/Всемирного банка либо ошибка PHP-скрипта прокси | Прокси уже повторяет запрос при лимите (429) автоматически; при повторяющейся ошибке — проверить лог PHP на сервере |
| Не загружается XLSX или не работает экспорт PDF/PPTX | Браузер не загрузил одну из библиотек с внешнего CDN | Проверить доступ к доменам CDN и консоль браузера; после локализации библиотек — проверить защищённые ассеты сборки |
| После обновления в интерфейсе видна старая версия | Кеш браузера (сама разметка отдаётся с `Cache-Control: no-cache`, но статика — с версионированным именем) | Обычное обновление страницы; при сомнении — жёсткое обновление (Ctrl+F5) |
| «Доступ только для владельца» на `/admin.php` | Вход выполнен не по общему паролю владельца (роль отличается от `full`) | Войти по общему паролю (поле логина пустым) |

Подробная диагностика (расположение логов, типовые ошибки) — в
[06_Руководство_администратора.md](06_Руководство_администратора.md#6-диагностика-и-логи).
