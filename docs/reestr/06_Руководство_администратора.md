# Руководство администратора

## 1. Роль администратора

Администратор (правообладатель) отвечает за развёртывание, обновление,
управление доступом и сопровождение приложения на хостинге. Отдельной панели
администрирования внутри самого приложения нет — управление пользователями
выполняется через служебный скрипт `admin.php`, остальное сопровождение — на
уровне сервера и репозитория.

## 2. Развёртывание и обновление

См. [04_Установка_и_развертывание.md](04_Установка_и_развертывание.md) и
[07_Эксплуатация.md](07_Эксплуатация.md#обновление).

## 3. Управление доступом

Приложение поддерживает два типа входа одновременно.

### 3.1. Общий пароль владельца

Задаётся один раз через `setup.php` (см. установку). Даёт полный доступ
(роль `full`) — все разделы приложения. Хеш пароля хранится в `config.php` на
сервере (bcrypt), в репозиторий этот файл не входит.

**Смена пароля владельца.** Отдельной формы смены пароля нет. Процедура:
удалить `config.php` на сервере и заново открыть `setup.php` с токеном
установки (`SETUP_TOKEN`, задаётся переменной окружения сборки или
генерируется случайно при сборке — см. `build.mjs`). Скрипт создаёт новый
`config.php` и после этого отключается.

### 3.2. Персональные аккаунты (для проверяющих)

Отдельная панель **`/admin.php`** — доступна только при входе с полным
доступом (роль `full`). Позволяет:

- **Создать аккаунт** — логин (3–32 символа, латиница/цифры/`. _ -`), ФИО,
  пароль (от 8 символов). Новый аккаунт всегда получает роль `expert`
  (проверяющий): при входе видит личный кабинет и демо-стенд, где скрыта
  загрузка собственных выгрузок пользователя.
- **Удалить аккаунт** — из списка одной кнопкой.

Пароли хранятся только как bcrypt-хеши в файле `/users.php` на развёрнутом
сервере (правами `0600`, в репозиторий не входит, вручную не редактируется).
Формы `admin.php` защищены CSRF-токеном сессии.

Роль `full` персональным аккаунтам через `admin.php` не назначается — это
осознанное ограничение: полный доступ даёт только общий пароль владельца.

### 3.3. Резервный экспертный пароль (опционально)

В `config.php` можно дополнительно задать `$AUTH_HASH_EXPERT` — общий пароль
с ролью `expert` без создания персонального аккаунта. Поле логина при таком
входе также остаётся пустым.

## 4. Прокси к UN Comtrade и WITS

- Запросы к обоим источникам идут через серверные прокси `/comtrade.php`
  и `/wits.php` с белым списком допустимых параметров (страны, коды,
  периоды, направление) — приложение никогда не даёт клиенту обращаться к
  внешним API напрямую.
- Ключ Comtrade Plus необязателен: если секрет `COMTRADE_KEY` не задан при
  сборке (`build.mjs`), прокси работает через публичный эндпоинт ООН с более
  строгими лимитами запросов.
- Публичный эндпоинт лимитирован — прокси автоматически повторяет запрос при
  ответе 429 (превышение лимита).

## 5. Резервное копирование

Что бэкапить на сервере (эти файлы правообладатель хранит на сервере,
дистрибутив из `dist/` их не содержит и не перезаписывает при обновлении):

- `config.php` — хеш общего пароля.
- `users.php` — персональные аккаунты проверяющих.
- `comtrade_key.php` — ключ Comtrade Plus, если задан отдельно от
  сборки.

Периодичность: ⚠️ ЗАПОЛНИТЬ (например, перед каждым обновлением дистрибутива
и по расписанию хостинга).

Остальное содержимое (статика, справочники) воспроизводимо из репозитория
сборкой `node build.mjs` и бэкапа не требует.

## 6. Диагностика и логи

- Ошибки авторизации и работы прокси — стандартный лог веб-сервера/PHP на
  хостинге (`error_log` Apache, лог PHP-FPM — расположение зависит от
  тарифа хостинга, см. панель управления).
- Типовая проблема «форма входа вместо приложения» — не создан `config.php`;
  решается через `setup.php` (см. установку).
- Типовая проблема «Прокси comtrade.php недоступен или вернул не JSON» —
  видна прямо в интерфейсе загрузки Comtrade/WITS; означает сбой на стороне
  публичного API ООН/Всемирного банка либо ошибку в PHP-скрипте прокси на
  сервере — проверяется логом PHP.
- Обновление подхватывается обычным обновлением страницы (без Ctrl+F5):
  разметка приложения отдаётся с заголовком `Cache-Control: no-cache`.

## 7. Персонал, необходимый для сопровождения

Специализированного персонала не требуется: администрирование сводится к
редким операциям (обновление дистрибутива, создание/удаление аккаунтов
проверяющих) и доступно одному человеку с базовыми навыками работы с
хостингом (загрузка файлов по FTP/SSH, чтение логов) и знанием командной
строки для сборки (`node build.mjs`). Отдельной круглосуточной поддержки
инфраструктура не требует — приложение статично со стороны сервера, кроме
прокси-скриптов к внешним источникам.
