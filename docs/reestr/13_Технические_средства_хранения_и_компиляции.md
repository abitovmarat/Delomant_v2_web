# Документация, содержащая описание технических средств хранения исходного текста и объектного кода программного обеспечения, а также технических средств компиляции исходного текста в объектный код

**Программа для ЭВМ:** Delomant Analytics System

**Версия заявляемого экземпляра:** 0.9

**Правообладатель:** ООО «ДЕЛОМАНТ ГРУПП»

**Территория разработки и сопровождения:** Российская Федерация

---

## 1. Назначение документа

Документ описывает технические средства, при помощи которых правообладатель
хранит исходный текст программы, подготавливает её к выпуску и размещает
готовый экземпляр на сервере.

Документ подготовлен для эксперта, проводящего проверку программного
обеспечения при включении в Единый реестр российских программ для
электронных вычислительных машин и баз данных.

## 2. Общие сведения о форме представления программы

Delomant Analytics System — веб-приложение. Оно исполняется двумя средами:

- клиентская часть (HTML, CSS, JavaScript) исполняется браузером
  пользователя;
- серверная часть (PHP 8) исполняется веб-сервером.

Оба используемых языка — интерпретируемые. Программа распространяется и
исполняется в виде исходного текста, который интерпретатор обрабатывает
непосредственно при выполнении.

**Компиляция исходного текста в объектный код в составе программы не
выполняется, объектный код не формируется и не хранится.** Отдельные
технические средства компиляции правообладателю не требуются и не
применяются.

Подготовка программы к выпуску сводится к сборке комплекта файлов для
размещения на сервере. Эта операция описана в разделе 5 и не является
компиляцией: содержимое файлов исходного текста при ней не преобразуется
в машинный или промежуточный код.

## 3. Технические средства хранения исходного текста

### 3.1. Основное хранилище

Исходный текст хранится в системе управления версиями Git.

| Параметр | Значение |
|---|---|
| Система управления версиями | Git |
| Платформа размещения репозитория | GitVerse (gitverse.ru) |
| Владелец репозитория | Организация правообладателя на платформе |
| Режим доступа | Закрытый (приватный) репозиторий |
| Территория размещения платформы | Российская Федерация |

GitVerse — российская платформа для работы с исходным кодом. Размещение
основного репозитория на ней обеспечивает независимость хранения и
сопровождения программы от иностранных сервисов.

Репозиторий хранит полную историю разработки: последовательность
изменений, ветви разработки и отметки версий. На момент подготовки
документа история содержит более 230 зафиксированных изменений начиная
с февраля 2026 года.

### 3.2. Рабочие копии

Разработчики работают с полными локальными копиями репозитория на
рабочих компьютерах. Git устроен так, что каждая рабочая копия содержит
всю историю изменений и является самостоятельным экземпляром
репозитория.

### 3.3. Резервное копирование

Резервные копии репозитория хранятся на контролируемой инфраструктуре
правообладателя на территории Российской Федерации. Порядок и
периодичность резервного копирования описаны в документации по
процессам жизненного цикла.

### 3.4. Сведения, не хранящиеся в репозитории

В целях безопасности в репозиторий не помещаются:

- `server/config.php` — хеши общих паролей доступа;
- `server/users.php` — персональные учётные записи и хеши паролей;
- `server/comtrade_key.php` — ключ доступа к сервису UN Comtrade Plus.

Эти файлы создаются непосредственно на сервере либо формируются при
сборке из защищённого хранилища секретов и в исходный текст не попадают.

## 4. Состав хранимого исходного текста

| Часть программы | Расположение | Содержание |
|---|---|---|
| Клиентское приложение | `index.html`, `scripts/`, `styles/` | Разметка, прикладная логика на JavaScript, стили |
| Серверная часть | `server/` | Компоненты на PHP 8: вход и разграничение доступа, защищённая выдача статических ресурсов, управление учётными записями, серверные посредники к открытым источникам данных, первичная настройка |
| Сборочный сценарий | `build.mjs` | Подготовка комплекта файлов для размещения на сервере |
| Конвейер выпуска | `.gitverse/workflows/` | Описание автоматической сборки и размещения |
| Справочные данные | `data/` | Справочники стран, регионов, товарных кодов и курсов валют |
| Сторонние библиотеки | `vendor/` | Браузерные библиотеки в неизменённом виде с текстами лицензий |
| Техническая документация | `docs/` | Внутренняя документация проекта |

Объём собственного исходного текста программы составляет около 22 тысяч
строк, из которых основная часть приходится на клиентское приложение и
серверные компоненты.

### 4.1. Сторонние библиотеки

Клиентские библиотеки хранятся в репозитории в виде неизменённых
браузерных дистрибутивов. Такое хранение выбрано, чтобы приложение не
загружало исполняемый код со сторонних сетей доставки содержимого во
время работы.

| Библиотека | Версия | Лицензия |
|---|---|---|
| SheetJS Community Edition | 0.20.3 | Apache-2.0 |
| JSZip | 3.10.1 | MIT либо GPL-3.0 |
| jsPDF | 2.5.1 | MIT |
| html2canvas | 1.4.1 | MIT |
| PptxGenJS | 3.12.0 | MIT |

Для каждой библиотеки в репозитории хранятся текст лицензии, исходный
адрес загрузки и контрольная сумма SHA-256 распространяемого файла.
Контрольные суммы позволяют убедиться, что содержимое библиотек не
изменялось.

## 5. Технические средства подготовки к выпуску

Компиляция не выполняется, поэтому компиляторы не применяются. Для
подготовки комплекта файлов используются средства, перечисленные ниже.

| Средство | Версия | Назначение |
|---|---|---|
| Node.js | 22 | Среда выполнения сборочного сценария |
| Сценарий `build.mjs` | В составе исходного текста | Формирование комплекта файлов для размещения |
| GitVerse CI/CD | Облачный исполнитель платформы | Автоматический запуск сборки и размещения |
| lftp | Из состава окружения исполнителя | Передача комплекта файлов на сервер по протоколу FTPS |

### 5.1. Что делает сборочный сценарий

Сценарий `build.mjs` запускается командой `node build.mjs` и формирует
каталог `dist/`. Выполняемые действия:

1. Копирование серверных компонентов на PHP и правил веб-сервера.
2. Размещение файлов клиентского приложения так, что напрямую, в обход
   проверки входа, они недоступны.
3. Копирование справочных данных и сторонних библиотек.
4. Предварительное сжатие крупных файлов для ускорения загрузки.
5. Подстановка отметки версии сборки, чтобы браузер получал обновлённые
   файлы, а не сохранённые ранее.
6. Копирование текстов лицензий сторонних библиотек.
7. Создание файла с ключом доступа к внешнему сервису, если ключ задан
   в защищённом хранилище секретов.

Содержимое файлов исходного текста при этом не преобразуется: на сервер
попадают те же тексты программы, что хранятся в репозитории.

### 5.2. Порядок выпуска

Штатный порядок:

1. Разработчик фиксирует изменения в основной ветви репозитория GitVerse.
2. Конвейер платформы автоматически получает исходный текст, разворачивает
   Node.js 22 и запускает сборочный сценарий.
3. Полученный каталог `dist/` передаётся на сервер по защищённому
   протоколу FTPS одним сеансом связи.
4. Обновление становится доступно пользователям при следующем открытии
   приложения.

Реквизиты доступа к серверу и ключ внешнего сервиса хранятся в защищённом
хранилище секретов платформы и в исходный текст не входят.

Предусмотрен также ручной порядок выпуска: сборка выполняется командой
`node build.mjs` на рабочем компьютере, а полученный каталог передаётся
на сервер FTPS-клиентом. Этот порядок применяется, если автоматический
конвейер недоступен.

## 6. Технические средства хранения размещённого экземпляра

Готовый экземпляр программы размещается на сервере, арендованном
правообладателем.

| Параметр | Значение |
|---|---|
| Хостинг-провайдер | cloud4box |
| Серверный узел | `web-3.cloud4box.com` |
| Адрес экземпляра | https://delomant-analytics-system.ru/ |
| Территория размещения | Российская Федерация |
| Веб-сервер | nginx перед Apache либо Apache напрямую |
| Обработка правил каталога | Apache с модулем `mod_rewrite` |
| Среда выполнения серверной части | PHP 8 |
| Протокол доступа пользователей | HTTPS |
| Протокол размещения обновлений | FTPS |

Отдельная система управления базами данных не применяется: программа не
хранит пользовательские данные на сервере. Учётные записи хранятся в
файлах с ограниченными правами доступа, пароли — в виде хешей bcrypt.

## 7. Средства разработки

Для работы с исходным текстом применяются общедоступные средства, не
входящие в состав программы и не влияющие на её работу:

- система управления версиями Git;
- текстовые редакторы и среды разработки по выбору разработчика;
- браузер для проверки клиентской части;
- веб-сервер с PHP 8 для проверки серверной части.

Специализированные средства сборки, компиляторы, генераторы кода и
системы управления зависимостями пакетов при подготовке программы не
используются. Файл `package.json` не объявляет внешних зависимостей:
сборочный сценарий работает на штатных возможностях Node.js.

## 8. Выводы

1. Исходный текст программы хранится в репозитории Git на российской
   платформе GitVerse, а также в рабочих и резервных копиях на
   инфраструктуре правообладателя в Российской Федерации.
2. Программа написана на интерпретируемых языках, компиляция исходного
   текста в объектный код не производится, объектный код не формируется
   и не хранится, технические средства компиляции не применяются.
3. Подготовка программы к выпуску выполняется сборочным сценарием на
   Node.js 22, который формирует комплект файлов для размещения без
   преобразования исходного текста.
4. Размещение обновлений выполняется средствами конвейера GitVerse CI/CD
   по защищённому протоколу FTPS на сервер, расположенный на территории
   Российской Федерации.
5. Все применяемые технические средства хранения и подготовки к выпуску
   находятся под контролем правообладателя и не зависят от иностранных
   сервисов.
