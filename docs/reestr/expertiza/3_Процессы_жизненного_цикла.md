# Документация, содержащая описание процессов, обеспечивающих поддержание жизненного цикла программного обеспечения, в том числе устранение неисправностей и совершенствование, а также информацию о персонале, необходимом для обеспечения такой поддержки

**Программное обеспечение:** «Delomant — Аналитика ВЭД»

## 1. Общая организация поддержания жизненного цикла

Поддержание жизненного цикла ПО обеспечивает правообладатель собственными силами.
Приложение развёрнуто по клиент-серверной схеме; сопровождение (обновление,
устранение неисправностей, развитие) выполняется правообладателем централизованно
на стороне сервера. Действий со стороны пользователей для поддержания жизненного
цикла не требуется — обновления доставляются автоматически при следующем открытии
приложения в браузере.

Процессы поддержания жизненного цикла включают:
- сопровождение и эксплуатацию (мониторинг работоспособности, резервное
  копирование, управление доступом);
- устранение неисправностей (приём обращений, диагностика, исправление, выпуск
  обновления);
- совершенствование (развитие функциональности, актуализация справочных данных,
  обновление компонентов);
- техническую поддержку пользователей.

## 2. Устранение неисправностей

### 2.1. Порядок приёма и обработки обращений
1. Пользователь направляет обращение в службу поддержки правообладателя (контакты
   — раздел 5).
2. Обращение регистрируется; определяется приоритет и характер неисправности.
3. Специалист сопровождения воспроизводит проблему, при необходимости анализирует
   логи веб-сервера/PHP на площадке размещения.
4. Выполняется исправление в исходном коде; изменения проходят проверку.
5. Собирается и выкладывается обновлённый дистрибутив (раздел 3).
6. Заявителю сообщается о результате устранения.

### 2.2. Диагностика
- Ошибки серверной части выявляются по журналам PHP и веб-сервера на площадке
  размещения.
- Ошибки клиентской части воспроизводятся в браузере (консоль разработчика).
- Проблемы внешнего источника (UN Comtrade) локализуются на уровне прокси
  `comtrade.php` (валидация параметров, кэш, ответы API).

> ⚠️ ЗАПОЛНИТЬ: типовые неисправности и штатные способы их устранения, расположение
> и порядок ротации логов на конкретной площадке.

## 3. Совершенствование и порядок обновления ПО

Обновление выполняется правообладателем централизованно на стороне сервера;
действий со стороны пользователей не требуется.

1. Внести изменения в исходный код (исправление или развитие функциональности).
2. Собрать новый дистрибутив: `node build.mjs`.
3. Выложить содержимое `dist/` на хостинг (замена файлов).
4. Файл `config.php` (пароль) при обновлении **не затрагивается**.
5. Изменение версии отражается в разделе «О программе».

**Обновление справочных данных** (курсы ЦБ РФ, страны UN Comtrade) —
перегенерация JSON офлайн-скриптами (`scripts/fetch_cbr_rates.js`,
`scripts/fetch_comtrade_countries.js`) и перевыкладка статических файлов.

> ⚠️ ЗАПОЛНИТЬ: политика версионирования (semver/дата), плановая периодичность
> обновлений, канал уведомления пользователей об обновлениях.

## 4. Резервное копирование

Резервному копированию подлежат: файл конфигурации `config.php` (bcrypt-хеш
пароля) и актуальные справочные данные (`data/*.json`).
Исходный код хранится в системе контроля версий.

> ⚠️ ЗАПОЛНИТЬ: периодичность резервного копирования и место хранения копий.

## 5. Информация о персонале, необходимом для поддержки

Поддержание жизненного цикла обеспечивается штатным персоналом правообладателя.
Для сопровождения ПО достаточно следующих ролей (могут совмещаться одним
специалистом):

| Роль | Квалификация | Функции |
|---|---|---|
| Разработчик (сопровождение) | Знание JavaScript (клиент), PHP 8 (сервер), Node.js/Python (сборка и офлайн-препроцессоры) | Исправление неисправностей, развитие функциональности, сборка дистрибутива |
| Администратор (DevOps) | Администрирование веб-хостинга (Apache/nginx, PHP), работа с FTPS/GitHub Actions | Развёртывание и обновление, управление доступом, резервное копирование, мониторинг, работа с логами |
| Специалист технической поддержки | Знание функциональности приложения | Приём и первичная обработка обращений пользователей |

Специальных сертификаций для сопровождения не требуется. Разработка и
сопровождение ведутся силами правообладателя на территории Российской Федерации.

> ⚠️ ЗАПОЛНИТЬ: фактический состав/численность команды сопровождения и ответственное
> подразделение правообладателя.
