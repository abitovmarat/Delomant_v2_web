# Перенос репозитория на GitVerse

Рабочая памятка. Задача — сделать российскую площадку GitVerse основным
местом хранения исходного текста, чтобы документация для реестра
описывала фактическое положение дел, а не желаемое.

## Зачем

Единственным местом хранения был github.com/abitovmarat/Delomant_v2_web.
Прямого запрета на GitHub в постановлении № 1236 нет, но зависимость
сопровождения от иностранной площадки — типовая причина вопросов при
экспертизе. Перенос убирает этот риск.

## Порядок действий

### 1. Импорт репозитория

1. Зарегистрировать организацию/аккаунт на gitverse.ru.
2. Создать репозиторий через импорт с GitHub.
3. **Не отмечать «Сделать репозиторий зеркалом».** У зеркал CI/CD не
   запускается, и автоматическая выкладка работать не будет.
4. Дождаться окончания импорта. Ограничения площадки: до 1 часа и до
   16 Гбайт. Наш репозиторий заведомо меньше: 233 коммита, три ветки
   (master, deploy/site-auth, feature/presentations), Git LFS не
   используется.
5. Проверить, что перенеслись история и все ветки.

### 2. Секреты

В настройках репозитория GitVerse завести те же секреты, что были в
GitHub Actions:

| Секрет | Назначение |
|---|---|
| `FTP_SERVER` | Адрес FTPS-сервера |
| `FTP_USERNAME` | Имя пользователя FTPS |
| `FTP_PASSWORD` | Пароль FTPS |
| `FTP_SERVER_DIR` | Корневой каталог сайта на сервере |
| `COMTRADE_KEY` | Ключ UN Comtrade Plus (необязательный) |

Значения берутся из настроек репозитория на GitHub. В исходный текст они
не попадают ни на одной из площадок.

### 3. Конвейер сборки

Конвейер уже подготовлен: `.gitverse/workflows/deploy.yml`. Синтаксис
GitVerse в целом совместим с GitHub Actions, поэтому файл повторяет
прежний: сборка `node build.mjs` на Node.js 22 и выкладка `dist/` одной
FTPS-сессией через lftp.

После первого запуска проверить:

- отработали ли `actions/checkout` и `actions/setup-node` на облачном
  раннере площадки;
- установился ли `lftp` через apt (если облачный раннер этого не
  разрешает — заменить на образ через параметр `container` либо
  зарегистрировать локальный раннер);
- совпадает ли метка `runs-on: ubuntu-latest` с доступными раннерами.

### 4. Переключение источника истины

1. Убедиться, что сборка и выкладка с GitVerse прошли успешно.
2. Переставить `origin` на GitVerse, GitHub при необходимости оставить
   вторым удалённым репозиторием как архивную копию.
3. Отключить workflow на GitHub, чтобы выкладку не выполняли две
   площадки одновременно.
4. Удалить `.github/workflows/deploy.yml`, когда переход подтверждён.

### 5. Резервное копирование

Зафиксировать, что резервные копии репозитория хранятся на
инфраструктуре правообладателя на территории РФ. Это понадобится в
документе о технических средствах хранения.

## Что затем идёт в документацию

После переноса в документе «Технические средства хранения исходного
текста и объектного кода» указываются:

- основное хранилище — репозиторий Git на площадке GitVerse;
- рабочие копии на компьютерах разработчиков;
- резервные копии на инфраструктуре правообладателя в РФ;
- средство сборки — Node.js 22 и сценарий `build.mjs`;
- выкладка — GitVerse CI/CD по протоколу FTPS.
