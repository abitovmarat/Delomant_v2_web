# Описание архитектуры системы

## 1. Общая схема

**Delomant — Аналитика ВЭД**, версия 0.9, построена по клиент-серверной схеме
с тонким серверным слоем. Основная прикладная логика выполняется в браузере.
PHP-часть отвечает за авторизацию, разграничение доступа, защищённую отдачу
статики, управление экспертными аккаунтами и проксирование внешних API.

```text
┌─────────────────────────────────┐
│ Браузер пользователя            │
│                                 │
│ index.html + main.js + main.css │
│ обработка, анализ, обогащение,  │
│ построение и экспорт отчётов    │
└──────────────┬──────────────────┘
               │ HTTPS, PHP-сессия
               ▼
┌───────────────────────────────────────────────┐
│ Веб-сервер: nginx → Apache/.htaccess → PHP 8 │
│                                               │
│ index.php     вход, роли, выдача приложения   │
│ asset.php     защищённая выдача статики       │
│ admin.php     экспертные учётные записи       │
│ setup.php     первичная настройка паролей     │
│ comtrade.php  прокси и кеш UN Comtrade        │
│ wits.php      прокси и кеш World Bank WITS    │
└──────────┬───────────────────┬────────────────┘
           │                   │
           ▼                   ▼
  UN Comtrade API       World Bank WITS API

Браузер дополнительно загружает закреплённые версии библиотек
SheetJS, JSZip, jsPDF, html2canvas и PptxGenJS из внешних CDN.
```

База данных не используется. Загружаемые пользователем таблицы обрабатываются
в оперативной памяти браузера и на сервер не передаются.

## 2. Клиентский слой

| Компонент | Назначение |
|---|---|
| `index.html` | Вёрстка одностраничного приложения и подключение библиотек |
| `scripts/main.js` | Загрузка файлов, обработка, анализ, обогащение и экспорт |
| `styles/main.css` | Оформление интерфейса и экспортируемых представлений |
| `data/*.json` | Справочники стран, регионов, кодов ТН ВЭД и курсов валют; служебный словарь компаний |
| `data/Logo.png` | Логотип приложения и материалов экспорта |

Клиент написан на HTML5, CSS3 и JavaScript без прикладного фреймворка. В
браузере выполняются:

- чтение CSV/XLS/XLSX;
- нормализация и объединение табличных данных;
- расчёт аналитических показателей и построение SVG-графиков;
- обогащение локальными справочниками и данными WITS;
- формирование CSV, XLSX, PNG, HTML, PDF и PPTX.

Приложение получает роль и логин пользователя через служебные `meta`-поля,
которые `index.php` подставляет при выдаче HTML. Для роли `expert` интерфейс
скрывает функции, требующие пользовательских файлов. Контрагентские сценарии,
которые технически присутствуют во внутренней реализации, не входят в
заявляемые функциональные характеристики версии 0.9.

## 3. Серверный слой

| Компонент исходного кода | Файл в дистрибутиве | Назначение |
|---|---|---|
| `server/index.php` | `/index.php` | Форма входа, PHP-сессия, роли `full` и `expert`, выдача приложения или экспертного кабинета |
| `server/asset.php` | `/asset.php` | Выдача JS, CSS, логотипа и JSON только после проверки сессии |
| `server/admin.php` | `/admin.php` | Создание и удаление персональных экспертных аккаунтов; доступ только роли `full` |
| `server/setup.php` | `/setup.php` | Одноразовое создание конфигурации с bcrypt-хешами паролей |
| `server/comtrade.php` | `/comtrade.php` | Валидация параметров, ограничение частоты, суточный файловый кеш и обращение к UN Comtrade |
| `server/wits.php` | `/wits.php` | Валидация параметров, суточный файловый кеш, запрос и разбор XML World Bank WITS |
| `server/htaccess` | `/.htaccess` | Rewrite-маршруты и запрет прямого доступа к внутренним файлам |

Basic Auth не используется. Контроль доступа выполняется PHP-сессией.
`.htaccess` перенаправляет обычные пути фронтенда, например
`scripts/main.js`, на `asset.php`; физически защищённая статика лежит в
`assets/*.dat` и напрямую закрыта.

Крупные статические файлы сборщик дополнительно сохраняет в виде `.gz`.
`asset.php` выбирает сжатую копию по `Accept-Encoding`, поддерживает ETag и
`Last-Modified` и требует ревалидацию кеша после обновления.

## 4. Состояние на сервере

Следующие объекты не входят в исходный репозиторий либо создаются во время
эксплуатации:

| Объект на развёрнутом сайте | Содержание | Порядок создания |
|---|---|---|
| `/config.php` | bcrypt-хеш пароля владельца и необязательного общего экспертного пароля | `setup.php` |
| `/users.php` | Персональные экспертные аккаунты и bcrypt-хеши их паролей | `admin.php` |
| `/comtrade_key.php` | Необязательный ключ Comtrade Plus | `build.mjs` из `COMTRADE_KEY` |
| `/cache/` | Суточный кеш ответов Comtrade/WITS и служебные отметки ограничения частоты | PHP-прокси |

Каталог сайта должен позволять PHP создавать `config.php`, `users.php` и
каталог `cache/`. Доступ к конфигурации, аккаунтам, ключу API, `.dat`-файлам и
каталогу кеша закрывается правилами `.htaccess`.

## 5. Сборка и публикация

`build.mjs` формирует каталог `dist/`:

1. удаляет предыдущий `dist/`;
2. копирует PHP-точки входа и `.htaccess`;
3. подставляет одноразовый `SETUP_TOKEN` в `setup.php`;
4. при наличии `COMTRADE_KEY` создаёт `comtrade_key.php`;
5. переносит HTML в `app/index.html`;
6. преобразует собственную статику в защищённые `assets/*.dat`;
7. создаёт gzip-копии крупных файлов;
8. добавляет метку сборки к URL собственных JS/CSS для обновления кеша.

Публикация выполняется GitHub Actions при отправке изменений в ветку
`master`: среда Node.js 22 собирает `dist/`, после чего каталог передаётся на
хостинг одной FTPS-сессией через `lftp`. Развёртывание выполняется без общего
удаления каталога сервера, поэтому эксплуатационные `config.php`, `users.php`
и `cache/` сохраняются между обновлениями.

## 6. Потоки данных

### 6.1. Пользовательская таблица

CSV/XLS/XLSX → память браузера → обработка → анализ и обогащение → локальное
скачивание результата. Исходный файл и обработанные строки серверу Delomant
не передаются.

### 6.2. UN Comtrade

Браузер → `/comtrade.php` → проверка сессии и параметров → файловый кеш либо
UN Comtrade API → JSON в браузер → анализ и экспорт.

### 6.3. World Bank WITS

Браузер → `/wits.php` → проверка сессии и параметров → файловый кеш либо
World Bank WITS API → разбор XML на сервере → нормализованный JSON в браузер.

### 6.4. Локальные справочники

`asset.php` → защищённый JSON в браузер → клиентское обогащение. Служебный
справочник компаний не выдаётся роли `expert`, а функции с его использованием
не заявляются в версии 0.9.

## 7. Модель безопасности

- единая PHP-сессия защищает приложение, собственную статику и API-прокси;
- cookie сессии имеет атрибуты `Secure`, `HttpOnly`, `SameSite=Lax`;
- после успешного входа идентификатор сессии регенерируется;
- пароли сохраняются только как bcrypt-хеши;
- панель управления аккаунтами доступна только роли `full` и использует
  CSRF-токен;
- внешние прокси принимают только валидированные параметры из белых списков;
- прямой доступ к внутренним каталогам, статике и конфигурации запрещён;
- пользовательские таблицы не сохраняются на сервере.

Доступность загрузки браузерных библиотек зависит от внешних CDN. Для
автономного дистрибутива их следует включить в состав защищённой локальной
статики; это отдельная задача подготовки фиксированной релизной версии.
