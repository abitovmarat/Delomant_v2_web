# Описание архитектуры системы

## Общая схема

Delomant — Аналитика ВЭД построена по клиент-серверной схеме с «тонким»
серверным слоем. Основная логика (обработка, анализ, обогащение, формирование
отчётов) выполняется в браузере на стороне клиента; серверная часть на PHP
отвечает за авторизацию, отдачу статики и проксирование внешних API.

```
Браузер (клиент)                     Сервер (PHP, shared-хостинг)      Внешние источники
────────────────                     ────────────────────────────      ─────────────────
SPA: index.html                      index.php  — вход, сессия
  scripts/main.js  ── запросы ──▶     asset.php  — отдача статики ──▶    (локальные .dat)
  styles/main.css                     comtrade.php — прокси      ──▶    UN Comtrade API
  xlsx (клиентский парсинг)           setup.php  — установка пароля
                                      config.php — bcrypt-хеш (не в репо)
данные: cbr_rates.json,
company_dictionary.json,
comtrade_countries.json
```

## Слои

### Клиентский слой (frontend)
- `index.html` — вёрстка одностраничного приложения, шесть модулей.
- `scripts/main.js` — вся прикладная логика (обработка, анализ, обогащение,
  генерация презентаций). Ванильный JavaScript, без фреймворка.
- `styles/main.css` — оформление.
- Библиотека `xlsx` — разбор Excel-файлов в браузере.
- Локальные данные-справочники в JSON.

### Серверный слой (backend, PHP)
- `server/index.php` — точка входа, форма входа, управление сессией.
- `server/asset.php` — отдача статики приложения только авторизованным
  пользователям.
- `server/comtrade.php` — прокси к UN Comtrade с белым списком параметров и
  файловым кэшированием ответов.
- `server/setup.php` — одноразовая установка пароля (bcrypt), отключается после
  создания `config.php`.
- `.htaccess` — Basic Auth на уровне сервера и правила перенаправления к
  `asset.php`.

### Сборка и выкладка
- `build.mjs` — сборщик: исходники приложения переносятся в `assets/*.dat`
  (расширение, которое не перехватывает nginx), закрываются `.htaccess` и
  отдаются наружу только через `asset.php` по проверке сессии. Фронтенд при этом
  продолжает обращаться к обычным путям — их проксирует `.htaccess`.
- Вспомогательные скрипты сбора данных (`scripts/fetch_*.js`) — офлайн-сбор
  справочников (курсы ЦБ, страны Comtrade) в статические JSON.

## Модель безопасности
- Единая авторизация: приложение, статика и прокси закрыты одной PHP-сессией.
- Cookie сессии: `Secure`, `HttpOnly`, `SameSite=Lax`.
- Пароль хранится только как bcrypt-хеш, вне репозитория.
- Прокси к внешнему API не является open-proxy: наружу уходят только
  валидированные параметры из белого списка.

## Потоки данных
1. **Пользовательская выгрузка**: файл Excel → парсинг в браузере → обработка →
   анализ → отчёт. Данные пользователя сервер не сохраняет.
2. **Статистика UN Comtrade**: клиент → `comtrade.php` (валидация, кэш) →
   UN Comtrade API → клиент → анализ → отчёт (с подписью об источнике).
3. **Обогащение**: локальные справочники (курсы ЦБ, компании) применяются на
   клиенте.
