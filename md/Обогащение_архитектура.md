# Обогащение данных: архитектура

**Дата:** 23 июля 2026
**Задача:** заменить раздел «Исследование» (AI-чат) на «Обогащение данных» — инструмент, который добавляет к таможенным данным полезные производные атрибуты. По умолчанию — без нейросети; API опционален и кэшируется.

---

## 0. Главная находка (по итогам реализации)

**Рабочие файлы компании уже содержат ручную разметку.** В листе `данные_финал` есть столбцы «Сегмент получателя», «Продукт получателя», «Более крупный холдинг/объединение», а цена за кг посчитана в «USD за КГ статистическая».

Поэтому обогатитель **не изобретает разметку, а учится на ней**:

1. Загружаем размеченный файл → обогатитель собирает словарь «ИНН → сегмент» из существующего столбца (существующая разметка **не перезаписывается**).
2. Загружаем новую сырую выгрузку → словарь + правила проставляют сегменты автоматически.

**Проверено на реальных данных:**
- Из размеченного файла выучено **93 компании**.
- На сырой выгрузке (2 824 строки без разметки) заполнено **100% строк**, из них «Прочее» только **16%** — то есть 84% ручной работы снято автоматически.
- Реальные сегменты компании: Переработка и производство (60%), Оптовая торговля (33%), Дистрибуция, Кондитерское производство, Розничная торговля, Прочее (складирование).

Оставшиеся «Прочее» доразмечаются через словарь в интерфейсе и запоминаются навсегда — точность растёт с каждым отчётом.

## 1. Сдвиг: что было и что будет

**Было — «Исследование» (AI-чат):**
`данные → метрики → нейросеть → текст-аналитика → заметки/слайды`
Требует API-ключ, результат непредсказуем, во многом дублирует то, что уже делают презентации детерминированно.

**Будет — «Обогащение данных»:**
`данные → конвейер обогатителей → данные + новые столбцы`
Детерминированно, предсказуемо, без обязательного API. Обогащённые столбцы автоматически усиливают анализ, презентации и экспорт.

AI-чат убирается: его функцию (рыночный текст) закрывают детерминированные генераторы презентаций.

---

## 2. Ядро: конвейер обогатителей

Обогащение — это набор независимых **обогатителей** (enrichers), применяемых к строкам данных. Каждый добавляет один или несколько столбцов.

```js
// Описание обогатителя
{
    id: 'segment',                       // идентификатор
    label: 'Сегмент получателя',          // название для UI
    description: 'Опт / розница / …',      // пояснение
    addsColumns: ['Сегмент'],             // какие столбцы добавляет
    needsApi: false,                      // работает ли без нейросети
    run(rows, headers, ctx) { … }         // применение к данным
}
```

**Принципы:**
- Каждый обогатитель самодостаточен и детерминирован по умолчанию.
- **Идемпотентность**: повторный запуск перезаписывает свои столбцы, не плодит дубли.
- Обогащённые столбцы — обычные столбцы данных: видны в таблице, доступны `findColumn`, работают в анализе/презентациях/экспорте без доработок.
- Порядок применения важен (например, нормализация названий → потом сегментация по нормализованному имени).

---

## 3. Четыре типа обогатителей

| Тип | Что делает | Пример | API |
|-----|-----------|--------|-----|
| **Вычисляемый** | Производные из существующих столбцов | Цена за кг, ценовой флаг | Нет |
| **Справочный** | Столбец по таблице соответствий | ТН ВЭД → категория, страна → регион | Нет |
| **Правило + словарь** | Классификация по ключевым словам + пополняемый словарь | Сегмент компании по названию/ИНН | Нет |
| **AI-ассистируемый** | Классификация непонятных, результат кэшируется в словарь | Сегмент для неоднозначных названий | Опц. |

Ключевой паттерн — **«Правило + словарь»**. Он уже частично реализован в `company_dictionary` (нормализация названий: `raw_pattern → canonical_name`). Обобщаем этот подход на любые классификации.

---

## 4. Хранение

- **Справочники** (ТН ВЭД → категория, страна → регион) — статические JSON в `data/` или встроенные таблицы. Меняются редко.
- **Пополняемые словари** (сегменты компаний) — накапливаются в `localStorage` (как `delomant_company_dictionary_autosave`), с экспортом/импортом в JSON для переноса между сессиями/пользователями.
- **Обогащённые столбцы** — добавляются в активные данные (`getActiveData`). Существуют только в текущей сессии данных; при повторной загрузке обогащение прогоняется заново (детерминированно — результат тот же).

---

## 5. Роль API — опциональная и кэшируемая

API не обязателен. Он подключается точечно, для одного шага — классификации названий, которые правила не распознали:

1. Правила классифицируют явное (90%): «ТД», «ОПТ» → опт; «МАРКЕТ» → розница; «ФАБРИКА» → производство.
2. Непонятные (10%) — по желанию отправляются нейросети **одним batch-запросом** (не по строке).
3. Ответ **сохраняется в словарь по ИНН/названию** → в следующий раз работает без API.

Так нейросеть — разовый «добиватель» справочника, а не постоянная зависимость. Со временем словарь покрывает почти всё, и API перестаёт быть нужен. Тот же принцип, что приняли для презентаций.

## 6. UI раздела «Обогащение данных»

Заменяет чат-интерфейс «Исследования». Ориентировочно:

- **Каталог обогатителей** — карточки/чекбоксы с названием, пояснением и пометкой «без ИИ / с ИИ».
- **Кнопка «Обогатить»** — применяет выбранные обогатители, добавляет столбцы, показывает сводку (сколько строк обогащено, распределение по категориям).
- **Просмотр результата** — мини-статистика: например, доля опт/розница/производство (это и есть «каналы сбыта» из презентаций).
- **Управление словарями** — правка правил и словаря сегментов, импорт/экспорт JSON.
- **Опционально «дообогатить через ИИ»** — кнопка для непонятных записей, с кэшированием.

## 7. Каталог обогатителей (что можно добавить)

По убыванию ценности:

1. **Сегмент получателя** (опт / розница / производство / HoReCa / дистрибуция) — правило+словарь. Даёт слайд «каналы сбыта», которого сейчас нет.
2. **Цена за кг + ценовой флаг** (норма / дорого / дёшево относительно рынка товара) — вычисляемый.
3. **Категория товара** по ТН ВЭД — справочный.
4. **Роль игрока** (крупный / средний / мелкий по доле объёма) — вычисляемый.
5. **Регион происхождения** (страна → макрорегион: ЮВА, Африка, СНГ…) — справочный.
6. **Флаги аномалий** (новый игрок, разовая поставка, скачок цены) — вычисляемый.

Каждый — отдельный обогатитель в реестре; включаются независимо.

---

## 8. Интеграция с приложением

- **Данные**: обогатители добавляют столбцы через `getActiveData`/`getActiveHeaders` — существующий механизм.
- **Анализ и презентации**: находят новые столбцы через `findColumn` автоматически. Например, слайд по сегментам соберётся, как только появится столбец «Сегмент».
- **Словари**: обобщаем существующий паттерн `company_dictionary` (нормализация) на классификации.
- **Экспорт**: обогащённые столбцы попадают в выгрузку данных как обычные.

---

## 9. План внедрения (по этапам)

**Этап A — каркас.** Реестр обогатителей + конвейер применения + добавление столбцов в данные. Один простой вычисляемый обогатитель (цена за кг) для проверки сквозного потока.

**Этап B — UI раздела.** Заменить чат «Исследования» на каталог обогатителей + кнопку «Обогатить» + сводку.

**Этап C — сегментация.** Обогатитель «Сегмент получателя» (правило+словарь) + управление словарём. Самый ценный.

**Этап D — справочники.** Категория товара, регион.

**Этап E — опциональный ИИ.** Batch-классификация непонятных с кэшем в словарь.

**Этап F — связка с презентациями.** Слайд «каналы сбыта / структура потребления» из сегментов.

## 10. Принятые решения

- ✅ **Сегменты** (как в эталонных презентациях): опт, розница, производство/переработка, кондитерская промышленность, HoReCa, дистрибуция, прочее.
- ✅ **Словарь сегментов**: начинаем с нуля — правила по ключевым словам классифицируют автоматически, словарь «ИНН → сегмент» накапливается ручными правками и переносится через JSON.

### Стартовые правила сегментации (по ключевым словам в названии получателя)

| Сегмент | Ключевые слова (подстроки, регистронезависимо) |
|---------|-----------------------------------------------|
| Опт | ОПТ, ТОРГОВЫЙ ДОМ, ТД, ТРЕЙД, TRADE, ОПТОВ |
| Розница | РИТЕЙЛ, RETAIL, МАРКЕТ, МАГАЗИН, X5, МАГНИТ, ЛЕНТА, ПЯТЁРОЧКА, ПЕРЕКР |
| Производство/переработка | ЗАВОД, ФАБРИКА, КОМБИНАТ, ПРОИЗВОДСТВ, ПЕРЕРАБОТ, АГРО |
| Кондитерская промышленность | КОНДИТЕР, СЛАДОСТ, ШОКОЛАД, КОНФЕТ |
| HoReCa | РЕСТОРАН, ОТЕЛЬ, КАФЕ, ГОСТИНИЦ, HORECA |
| Дистрибуция | ДИСТРИБ, DISTRIB, ЛОГИСТИК |
| Прочее | (не распознано ни одним правилом) |

Порядок проверки — сверху вниз, первое совпадение выигрывает; список уточняется по мере просмотра реальных данных. Приоритет спорных случаев (напр. «ТД» внутри «кондитерский ТД») донастроим на данных.
