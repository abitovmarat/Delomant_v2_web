## 1. Коротко (TL;DR)

1. **Конструктор уже устроен правильно** — это блочная сборка слайдов по шаблону компании ([main.js:7498](../scripts/main.js), модуль Presentation Constructor). Выбрасывать и переписывать не нужно.
2. **Главная ошибка — ставка на нейросеть как обязательное звено.** Данные структурированы, все нужные числа (CAGR, доли, лидеры, покрытие ТОП-N) **уже считаются детерминированно** в `computeSlideMetrics` ([main.js:8821](../scripts/main.js)). Значит 80–90% текста для слайда можно собирать **шаблонами из чисел, без нейронки** — предсказуемо, мгновенно, бесплатно, без интернета.
3. **Чего реально не хватает** по сравнению с эталонными презентациями компании:
   - **заголовков-выводов** (action title) — сейчас заголовок слайда это просто «Объёмы», а в эталоне это «Импорт кешью демонстрирует устойчивый рост: за три года поставки выросли на 41%…»;
   - **качественной текстовой интерпретации** справа от диаграммы (сейчас — либо ручной ввод, либо непредсказуемая нейронка);
   - **режима «мастер»** — одной кнопки «собери стандартный отчёт по товару», которая сама расставит слайды в порядке шаблона.
4. **Предложение:** сделать генерацию текста и заголовков **детерминированной** (шаблоны из метрик), а нейросеть оставить как **опциональную полировку**. Плюс добавить **пошаговый мастер** поверх существующего конструктора.
5. **Аналоги:** визуальный стиль эталонных слайдов — это **think-cell** (стандарт McKinsey/BCG). AI-генераторы (Gamma, Plus AI, Beautiful.ai, Tome) — это как раз тот путь «из промпта», который не устраивает. Ниша Delomant уникальна: **данные ВЭД + автосборка брендовой презентации** — прямых конкурентов на этой связке почти нет (см. раздел 9).

## 3. Эталон компании — разбор реальных презентаций

Разобрал презентацию «Анализ российского рынка орехового сырья» (`обучение/pdf_pages`, 21 слайд) и остальные PDF в `обучение/посмотреть`. Структура **жёстко шаблонная и повторяемая** — это большое преимущество для автоматизации.

### Скелет отчёта (из оглавления, слайд 2)

```
1. Введение                              ← текст-аналитика
2. Анализ объёмов импорта <ТОВАР A>
   2.1 Динамика поставок (нат. + денеж.)  ← блок volumes
   2.2 Структура и цены по странам         ← блоки countries + price-dynamics
   2.3 Структура по изготовителям/получат. ← блок sankey-manufacturer
   2.4 Структура по поставщикам/сегментам  ← блок sankey-sender
   2.5 Поквартальная динамика цен          ← блок quarterly-prices
3. Анализ объёмов импорта <ТОВАР B>       ← тот же набор
4. Резюме тенденций                        ← текст-аналитика
5. Рекомендации                            ← таблица-матрица
```

**Вывод:** существующие блоки уже покрывают ~90% шаблона. Не хватает как отдельных сущностей: **введение** (генерируемое), **резюме** (генерируемое), **таблица-рекомендаций** (сравнительная матрица товаров).

### Восемь типов слайдов и их «золотой стандарт»

1. **Титул** — синий фон, логотип, название, «Часть I», год. ✅ есть.
2. **Оглавление** — иерархия разделов с номерами страниц. ✅ есть (`toc`).
3. **Введение** — синяя шапка + 3 буллета аналитики с конкретными числами и трактовкой («рынок кешью вырос вдвое, драйвер — Вьетнам, растёт роль опта с 30% до 47%»). ⚠️ сейчас только ручной `text`.
4. **Слайд с диаграммой (эталон, слайд 5)** — **это ядро.** Устроен так:
   - **заголовок-вывод** во всю ширину: «Импорт кешью демонстрирует устойчивый рост: в среднем за три года поставки выросли на 41% в натуральном и на 29% в долларовом выражении…»;
   - слева — 3 диаграммы (тыс. тонн, млн руб, млн долл) со **плашкой CAGR**, подписями значений, **процентами прироста между столбцами** и линией тренда;
   - справа — 3 буллета текстовой интерпретации.
   - ⚠️ Сейчас: заголовок = «Объёмы», интерпретация = ручная/нейронка, стрелки прироста между барами — под вопросом.
5. **Мульти-визуал (слайд 6)** — 2 таблицы + линейный график цен по странам + текст. ⚠️ частично (`countries` + `price-dynamics` раздельно).
6. **Sankey (слайд 7)** — потоки Изготовитель→Получатель. ✅ есть.
7. **Резюме (слайд 19)** — 6 буллетов выводов по всему рынку. ⚠️ сейчас ручной.
8. **Рекомендации (слайд 20)** — сравнительная матрица «аспект × товар» + ключевой вывод. ❌ такого блока нет.

### Визуальные детали, которые делают слайд «дорогим»

- **Плашка `CAGR NN%`** над каждой диаграммой.
- **Стрелки/подписи прироста между столбцами** (`+56,2%`, `27,4%`) с тонкой линией тренда.
- **Неполный период выделен цветом** (Q1 2025 — бледнее, это не полный год).
- **Заголовок — всегда вывод, а не название** («что это значит», а не «что показано»).

## 4. Диагноз: почему путь «через нейронки» не устраивает

| Проблема | Причина | Следствие |
|----------|---------|-----------|
| Непредсказуемость | Нейросеть каждый раз пишет по-разному | Нельзя доверять без вычитки |
| Зависимость | Нужен API-ключ, интернет, оплата | Не «нажал — готово» |
| Риск ошибок в числах | Нейросеть может исказить цифру из метрик | Для аналитики недопустимо |
| Российские сети не работают из браузера | CORS / токены GigaChat, YandexGPT | Обещание есть — результата нет |
| Заголовки остаются шаблонными | AI пишет только боковой текст, не action-title | Слайд не дотягивает до эталона |

**Корень проблемы:** нейросеть поставлена на роль, для которой она не нужна. Когда у тебя уже есть точные числа (`cagrWeight = 41`, `leaderShare = 99.6`), фраза «поставки выросли на 41%, доля Вьетнама — 99,6%» собирается **шаблоном** — детерминированно и без риска.

Нейросеть полезна для другого: перефразировать суховатый шаблон в живой текст, добавить внешний контекст рынка. Но это **полировка**, а не фундамент.

## 5. Центральная идея: детерминированная генерация текста из метрик

**Принцип: числа и выводы — из данных шаблоном; нейросеть — опциональная косметика поверх.**

### Как это выглядит на практике

`computeSlideMetrics` уже отдаёт для слайда «Объёмы»:
```js
{ cagrWeight: 41, cagrUsd: 29, cagrRub: 50, trend: 'growth',
  latestWeight: 14.5, firstYear: '2022', lastYear: '2024', ... }
```

Из этого **шаблон** собирает и заголовок, и тезисы:

**Заголовок-вывод (шаблон с ветками по `trend`):**
> «Импорт <товар> демонстрирует **устойчивый рост**: за <2022–2024> поставки выросли на **41%** в натуральном и на **29%** в долларовом выражении».

Ветки: `growth` → «устойчивый рост», `decline` → «сокращение», `stable` → «стабильные объёмы». Пороговые слова («умеренный/бурный») — по величине CAGR.

**Тезисы справа (3 шаблона с подстановкой чисел):**
> • Натуральный объём вырос с <7,3> до <14,5> тыс. тонн (CAGR <41%>).
> • Рост в долларах (<29%>) отстаёт от физического (<41%>) — снижается средняя цена закупки.
> • Рублёвая стоимость растёт быстрее (CAGR <50%>) из-за курса — давление на себестоимость.

Это **буквально текст эталонного слайда 5**, собранный из чисел без нейросети.

### Что нужно написать

- Библиотека **текстовых шаблонов** на каждый тип слайда (`volumes`, `countries`, `price-dynamics`, `sankey-*`, `quarterly-prices`), с ветвлением по трендам/порогам. Чистый JS, ~1 функция на тип.
- Отдельно — **генератор `Введения`** (сводит метрики нескольких товаров в 3 абзаца) и **`Резюме`** (выводы по всему отчёту).
- Заголовки-выводы для аналитических слайдов — из того же движка.

### Где остаётся нейросеть (опционально)

- Кнопка «Оживить текст» — берёт готовый шаблонный текст и просит сеть перефразировать (низкий риск: числа уже на месте).
- Кнопка «Добавить рыночный контекст» — внешние данные (это единственное, что сеть реально добавляет сверх наших данных).
- Работает с любой сетью, но **не обязательна ни для чего**.

## 6. Предлагаемый пошаговый мастер (поверх конструктора)

Конструктор оставляем для тонкой правки. Сверху добавляем **мастер из 4 шагов** — для «любого пользователя».

**Шаг 1. Что анализируем.** Пользователь выбирает товар(ы) по ТН ВЭД (мультивыбор). Приложение показывает, сколько строк/лет/стран нашлось — сразу видно, хватает ли данных.

**Шаг 2. Что включить.** Чекбоксы стандартных разделов (динамика, страны, цены, изготовители, поставщики, кварталы). По умолчанию всё включено — это шаблон компании. Можно снять лишнее.

**Шаг 3. Оформление.** Название отчёта, «Часть», год, контакты. Один экран.

**Шаг 4. Собрать.** Кнопка **«Собрать отчёт»**:
- расставляет слайды в порядке шаблона (титул → оглавление → введение → по каждому товару блок разделов → резюме → рекомендации → контакты);
- заполняет **заголовки-выводы и текст детерминированно** из метрик;
- открывает результат в конструкторе — правь и экспортируй.

Итог: **3–4 клика от данных до готовой брендовой презентации**, без единого промпта и без обязательной нейросети. Тонкая доводка — в существующем конструкторе.

## 8. Дорожная карта (по возрастанию эффекта/усилий)

**Этап 1 — «текст без нейронки» (максимальный эффект, малые усилия).**
Движок детерминированных шаблонов для текста и заголовков-выводов. Сразу поднимает качество всех аналитических слайдов и убирает зависимость от нейросети. Нейронку — в опцию «оживить».

**Этап 2 — «пошаговый мастер».**
4 шага и кнопка «Собрать отчёт». Превращает конструктор в инструмент «для любого».

**Этап 3 — «недостающие блоки».**
Введение, Резюме, Рекомендации-матрица, мульти-визуал стран.

**Этап 4 — «think-cell-полировка».**
Стрелки прироста, приглушение неполного периода, единый стиль подписей — чтобы слайды были неотличимы от ручных.

**Этап 5 — опционально — российские нейросети.**
GigaChat/YandexGPT через PHP-прокси на хостинге (обсуждали ранее) — только для «оживления» и рыночного контекста, не для чисел.

## 9. Моё мнение (честно)

- **Архитектуру не ломать.** Блочный конструктор, привязанный к шаблону компании и к её данным, — это правильно и это уже редкое конкурентное преимущество. Проблема не в нём.
- **Ставка на нейросеть как ядро — стратегическая ошибка для этого продукта.** Аналитику по таможенным данным нельзя строить на генераторе, который «иногда придумывает». Ценность Delomant в том, что **каждое число проверяемо и берётся из декларации** — это надо сохранить, а не размывать нейросетью.
- **Детерминированные шаблоны дадут 90% результата** и снимут почти все претензии к текущему пути. Это не «упрощение» — консалтинговые отчёты десятилетиями собираются по фиксированным формулировкам, и это считается признаком качества, а не бедности.
- **Мастер важнее красоты.** «Любой пользователь по шагам» — это про снятие решений с пользователя (за него уже решил шаблон компании), а не про добавление возможностей. Меньше выбора на входе = лучше результат.
- **Нейросеть держать, но честно назвать её роль:** необязательная полировка формулировок и внешний контекст. Тогда и российские сети через прокси станут приятным бонусом, а не критичной зависимостью.
- **Реалистичный идеал** здесь достижим на 80–85%: шаблон компании стабилен, данные структурированы. Оставшиеся 15% (тонкие смысловые выводы, нестандартные рынки) — это ручная правка в конструкторе, и это нормально.

## 10. Аналоги — кто и что делал до нас

### Визуальный стиль аналитических слайдов
- **think-cell** — надстройка над PowerPoint, стандарт в McKinsey, BCG, Bain. Автоматизирует ровно такие графики: **плашки CAGR, стрелки прироста между столбцами, waterfall, mekko**. Эталонные слайды Delomant визуально сделаны в его стилистике (возможно, буквально в нём). Ориентир №1 по визуалу.
- **Mekko Graphics** — прямой конкурент think-cell, тот же класс задач.

**Вывод:** эти инструменты автоматизируют *графики из чисел*, но не *текст-выводы* и не привязаны к отраслевым данным. Delomant может закрыть и то, и другое.

### AI-генераторы презентаций (путь «из промпта»)
- **Gamma**, **Plus AI** (для Google Slides/PowerPoint), **Beautiful.ai**, **Tome**, **Decktopus**, **Pitch** — генерируют слайды из текстового запроса или темы.

**Вывод:** это ровно тот путь, который «не нравится» — красиво, но из промпта, без привязки к вашим данным и бренду, с непредсказуемым содержанием. Их слабость — как раз ваша сила (точные данные + фиксированный шаблон).

### Данные → визуализация
- **Rows AI**, **Coefficient**, **Power BI**, **Tableau (Story Points)**, **Looker Studio** — превращают данные в дашборды/графики.

**Вывод:** дают визуализацию, но не собирают **брендированную повествовательную презентацию с выводами**. Между «дашбордом» и «отчётом для клиента» — пропасть, которую Delomant как раз перекрывает.

### Отраслевые — данные ВЭД / таможня
- **ImportGenius**, **Panjiva (S&P Global)**, **Seldon.Basis**, **ТКС/Тамдок**, **Data.gov-выгрузки** — поставляют таможенные данные и базовую аналитику.

**Вывод:** это источники и таблицы, но **не генераторы клиентских презентаций**. Никто из них не делает «загрузил декларации → получил брендовый аналитический отчёт по шаблону». **Это и есть незанятая ниша Delomant.**

### Итог по аналогам
Прямого конкурента на связке **«таможенные данные ВЭД + автосборка брендовой аналитической презентации с выводами»** фактически нет. Есть сильные инструменты по отдельным кускам (think-cell — графики, Gamma — генерация из промпта, ImportGenius — данные). Стратегически верно **не копировать AI-генераторы**, а довести до автоматизма то, что уже начато: данные → шаблон компании → готовый отчёт.

## 11. Открытые вопросы к вам

1. **С какого этапа начинаем?** Рекомендую с Этапа 1 (детерминированный текст) — он даёт наибольший эффект при малых усилиях.
2. **Формулировки шаблонов** — соберём из ваших эталонных PDF (введение, интерпретации, резюме) или напишем заново в том же стиле?
3. **Блок «Рекомендации-матрица»** (слайд 20) — нужен? Он узнаваемый и сильный, но требует отдельной верстки.
4. **Нейросеть** — оставляем как опцию «оживить/добавить контекст», или на данном этапе убираем из интерфейса совсем, чтобы не путала?
5. **Мультитоварные отчёты** (как в эталоне: кешью + арахис в одном отчёте) — нужны сразу или сначала однотоварные?
